# v0.3 — Unified Funnel Overlay

## Цель

Сделать один совмещённый интерактивный график, на котором одновременно отображаются:

1. Воронка магазина.
2. Рекламный след.

Главный режим — нормализованный индекс. Цель — увидеть, совпадает ли движение рекламы с движением заказов и воронки.

## Главный продуктовый тезис

Стандартная рекламная атрибуция WB может не показывать весь эффект рекламы. Реклама может влиять на позиции, органику, переходы в карточку и общий поток заказов. Поэтому нужно смотреть не только рекламные заказы, а общий halo effect:

```text
рекламный след → движение общей воронки магазина
```

## Метрики графика

### Воронка магазина

- `open_count` — переходы в карточку.
- `cart_count` — добавления в корзину.
- `order_count` — заказы в воронке.
- `buyout_count` — выкупы.

### Рекламный след

- `ad_views` — рекламные показы.
- `ad_clicks` — рекламные клики.
- `ad_atbs` — рекламные корзины.
- `ad_orders` — рекламные заказы.
- `ad_spend` — рекламный расход.

### Дополнительные метрики

- `supplier_orders` — все заказы из Orders API.
- `orders_sum` — сумма заказов.

## Основной endpoint

```http
GET /api/overlay/metrics
```

Параметры:

```text
date_from=YYYY-MM-DD
date_to=YYYY-MM-DD
scope=store|nm|selection|group
nm_id=123456789
nm_ids=111,222,333
group_id=1
mode=indexed|raw
```

Примеры:

```bash
curl 'http://localhost:8000/api/overlay/metrics?mode=indexed'

curl 'http://localhost:8000/api/overlay/metrics?scope=nm&nm_id=910001001&mode=indexed'

curl 'http://localhost:8000/api/overlay/metrics?scope=selection&nm_ids=910001001,910001003&mode=indexed'

curl 'http://localhost:8000/api/overlay/metrics?scope=group&group_id=1&mode=indexed'
```

## Нормализованный индекс

Для каждой линии система ищет первое ненулевое значение в периоде и принимает его за 100.

Формула:

```text
indexed_value = current_value / first_non_zero_value * 100
```

Если у линии нет ненулевых значений, она остаётся нулевой.

Это позволяет сравнивать форму движения метрик разного масштаба:

- переходы в карточку;
- заказы;
- рекламные клики;
- рекламный расход.

## Frontend

График реализован на ECharts.

Требования:

- одна временная шкала;
- кликабельная легенда;
- включение/выключение каждой линии;
- hover tooltip по дню;
- вертикальный axis pointer;
- zoom по периоду;
- режим `indexed` по умолчанию;
- режим `raw` для абсолютных значений.

## Почему не два графика

Два отдельных графика не решают исходную задачу. Смысл продукта именно в наложении линий, чтобы пользователь мог визуально проверять:

- есть ли синхронность между рекламой и воронкой;
- есть ли задержка между кликами и заказами;
- есть ли рост общего спроса, который WB не атрибутировал как рекламный заказ;
- есть ли товар, где реклама растёт, а воронка не реагирует.

## Источники данных внутри системы

```text
FunnelDailyStat       → воронка магазина
DailyProductMetric    → рекламный след + orders API
ProductGroupItem      → группы товаров
```

Сведение:

```text
date + nmId
```

Для всего магазина:

```text
GROUP BY date
```

Для артикула:

```text
WHERE nm_id = ...
```

Для нескольких артикулов:

```text
WHERE nm_id IN (...)
```

Для группы:

```text
JOIN product_group_items
```

## Ограничения

- График показывает корреляцию, не строгую причинность.
- Для реального кабинета нужно проверить форму ответа WB Analytics API.
- Для длинной истории нужно регулярно сохранять данные у себя.
- ECharts сейчас грузится через CDN. Для production можно скачать файл и отдавать локально.
